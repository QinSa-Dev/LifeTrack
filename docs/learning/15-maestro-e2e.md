## 3. 相关技术概念

### 3.1 为什么是 Maestro，而不是坐标点击

「让 agent 点模拟器」有两条路：

| 路线 | 代价 |
| --- | --- |
| `osascript` / `cliclick` 点坐标 | 需要把**宿主 App** 加进「系统设置 → 隐私与安全性 → 辅助功能」，否则报 `execution error: "osascript" 不允许辅助访问。(-1728)`；而且窗口一挪就点错 |
| **Maestro** | 在模拟器里装自己的 XCTest driver 驱动界面（`maestro` 官方 iOS driver），**不需要辅助功能权限**；按文字/id 找元素，不靠坐标 |

选后者。代价是它自己是一套新工具（要装、要学选择器语义）。

### 3.2 它怎么找到元素：可访问性文字（accessibilityText）

iOS 上 Maestro 读的是元素的 **accessibility 文字**，对 React Native 来说就是 `Text` 的内容、
以及被标成单个可访问元素的容器文字。所以：

- 断言/点击的目标必须是**屏幕上真实存在的文字**（不是代码里的变量名）；
- 想用一个元素的文字做锚点时，先 `maestro hierarchy` 看它到底被暴露成什么。

### 3.3 匹配是**全文匹配**，部分匹配要自己写 `.*`

这是本项踩的第一个坑。`assertVisible: '时间轴'` 能过，是因为页面头部标题恰好就是「时间轴」；
但底部标签栏的文字是 **`时间轴, tab, 1 of 5`**（Maestro 帮忙拼了「第几个 tab」），
所以 `tapOn: '事件'` **找不到任何东西**。

规矩：**默认按正则全文匹配**；要用片段就显式写 `.*事件, tab.*`。

### 3.4 列表行的文字会被**合并成一个**元素

- 时间轴的 `RecordRow`（不可点）把标题、取值、时间、删除按钮暴露成**分开**的多个元素；
- 事件页/周期页的 `ListRow`（可点）会被合并成**一条**，例如
  `Maestro喝水, 未分组 · 计数, 计数`。

所以点「事件列表里的某个定义」要写 `.*Maestro喝水.*`，不能写 `Maestro喝水`（全文匹配不上）。

更容易咬人的是：**整行可点时，行内的按钮也会被一起合并进去**。周期实例页的每日记录行
在视图树里只有一条：`2026-10-22, （无内容）, 删除`——`tapOn: '删除'` 找不到任何东西，
因为「删除」不是一个独立元素。这不只是测试的问题：**读屏用户同样永远聚焦不到那个按钮**。

修在 `src/components/ListRow.tsx`：让「文字区」自己当无障碍按钮
（`accessible` + `accessibilityRole="button"`），整行不做无障碍元素。
点击区不变（仍能点整行进入编辑），行内按钮各归各。
修完之后 `tapOn: { text: '删除', below: { text: '每日记录' } }` 就能命中。

### 3.5 键盘：`hideKeyboard` 在中文输入法下会失败

`hideKeyboard` 报
`Couldn't hide the keyboard. This can happen if the app uses a custom input or doesn't expose a standard dismiss action.`
改用 **`pressKey: Enter`**：单行 `TextInput` 回车即失焦（RN 默认 `blurOnSubmit`），键盘跟着收起。

另外**数字键盘（`keyboardType="number-pad"`）没有回车键**，`pressKey: Enter` 也救不了。
所以流程里刻意**不填**「平均周期长度」这个可选字段（`CycleDefinitionForm.tsx` 里它是 number-pad）。

### 3.6 Expo Go 里「重新打开」不等于「重新加载」

`openLink: exp://127.0.0.1:8081` 在同一个项目上只是把 App bring 到前台，**不会重载 JS**、
更不会回到根路由。上一次跑完停在回收站，下一次就还停在回收站（于是断言「时间轴」失败）。

归一化的写法是**先杀再开**：

```yaml
- launchApp:
    stopApp: true          # 杀掉 Expo Go（不清数据）
- openLink: exp://127.0.0.1:8081
- extendedWaitUntil:
    visible: '时间轴, tab, 1 of 5'   # 用标签栏文字当锚点，确认真的落在根页面
    timeout: 120000
```

**绝对不要用 `launchApp: clearState: true`**：在 Expo Go 里这个 App 就是 Expo Go 自己，
`clearState` 会清空容器——**包括本项目的 SQLite 库**。

### 3.7 同名按钮：**改文案**比找选择器更稳

回收站「永久删除」原来会弹一个 `Alert`，弹窗里的确认按钮文字**和列表行里的按钮一模一样**
（都叫「永久删除」）。按文字点会撞车（弹窗在视图树里排在列表之后）。

第一版用**相对选择器**解决：弹窗正文里有「无法恢复」，确认按钮在它**下面**——

```yaml
- tapOn:
    text: '永久删除'
    below:
      text: '.*无法恢复.*'
```

这招在回收站只有**一个**区时能用。后来回收站多了「已删除的周期记录」区，列表里就有两个
「永久删除」了，而周期区那个按钮的顶边恰好落在弹窗正文的顶上之下——`below` 会先命中
**被弹窗挡住的那个列表按钮**（点下去没反应，弹窗还在），`07` 第一次跑就是这么挂的。

> `below` 的判定按**顶边**比较，命中的是「第一个满足条件的元素」，**不是「最近的那个」**。
> 别把它当「就近匹配」用。

最后改成**让文案本身不重名**：弹窗的确认按钮叫「彻底删除」（`src/app/records/deleted.tsx`）。
全文匹配下「彻底删除」全局只有一个，选择器不用绕；顺带也让读屏能分清
「列表里的入口」和「弹窗里的最后一步」。按钮文字与正文「将被彻底删除」也对得上。

**结论**：能靠文案消歧就别靠几何关系——文案是稳定的，坐标不是。
（两个区各有一个「恢复」按钮时，仍会用 `below: 已删除的周期记录` 指向区标题，
这种「同区内的按钮」用相对选择器是合适的。）

### 3.8 点击落在**标签栏**上：先滚动再点

统计页的对比 `Chip` 在页面最底部，紧贴标签栏。**不滚动就点，坐标会落到标签栏上**，
于是「点了对比」的结果是**跳到了时间轴**（本项踩过的第二个坑：断言「概览」失败，dump 出来是时间轴）。

所以流程里先 `scrollUntilVisible` 到它下面那行「对照窗口：…」，让 `Chip` 完整露出来再点。

### 3.9 断言之外，还要**直接读库**核对

界面断言会被「元素文字恰好相同」骗过（比如回收站那步）。真正的证据在库里：

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcrun simctl get_app_container booted host.exp.Exponent data
# → …/Documents/ExponentExperienceData/@anonymous/lifetrack-<uuid>/SQLite/lifetrack.db
```

```bash
sqlite3 lifetrack.db "select count(*), sum(deleted_at is not null) from event_records;"
```

这就是「点记录到底有没有写进库」的最终答案（第 6 节有真实数字）。

### 3.10 页头的「返回」也在滚动内容里

本项目所有页面都是 `Screen scroll` + `Header`（`src/components/`），**页头不是固定的**，
它跟着内容一起滚。这在界面上的代价是「滚到下面想返回，得先滚回顶部」；
在自动化里的代价更直接：`tapOn: '返回'` 会报

```
Element not found: Text matching regex: 返回
```

…而屏幕上并不是没有返回，只是它现在在屏幕上方之外。补 `08` 时（周期实例页多了一张月视图卡片、
页面更长），`07` 就在这一步挂了——**它不是被新功能改坏的，而是「本来勉强够用」的假设被撑破了**。

做法很简单：点之前先把它滚回视野（已经可见时 `scrollUntilVisible` 会立刻返回）：

```yaml
- scrollUntilVisible:
    element:
      text: '返回'
    direction: UP
- tapOn: '返回'
```

顺带一提，这也解释了为什么 `03` 之类的流程结尾不再需要返回——它们断言完就结束，
不需要再点页头。

## 4. 关键片段逐条解释

### 4.1 子流程：自己造数据，不依赖手工数据

`subflows/record-once.yaml` 先判断「Maestro 喝水」在不在，不在就新建（`runFlow` + `when`），
然后点进去记一次：

```yaml
- runFlow:
    when:
      notVisible: '.*Maestro喝水.*'
    commands:
      - tapOn: '+ 新建事件'
      - tapOn: '例如：喝水'
      - inputText: 'Maestro喝水'
      - pressKey: Enter
      - scrollUntilVisible:
          element:
            text: '创建'
          direction: DOWN
      - tapOn: '创建'
```

三个细节：**`inputText` 的中文能直接打进去**（不用换 ASCII）；提交按钮在表单最底部，
要先 `scrollUntilVisible`；键盘要先收起来，否则点击会打在键盘上。

> 名字统一带 `Maestro` 前缀，跑完一眼就能认出「这是测试造的」。

### 4.2 记录一次：默认值就够，不需要敲数量

记录页的「手动记录」数量框默认就是 `1`，而且它**没有 placeholder**（无法用文字定位）。
流程直接用默认值，只点「记录」，然后断言顶部提示：

```yaml
- tapOn: '记录'
- assertVisible: '.*已记录：.*'
```

### 4.3 删除 → 撤销：软删除是可以反悔的

```yaml
- tapOn:
    text: '删除'
    index: 0        # 时间轴第一行 = 最新那条
- assertVisible: '.*已删除：.*'
- tapOn: '撤销'
- assertNotVisible: '.*已删除：.*'
```

`index: 0` 是 Maestro 的同名元素消歧手段（这里有多行「删除」按钮）。
这条流程**净值 0**：删的是最新一条，随即又恢复，不动库。

### 4.4 回收站：恢复与真删都验，且只动自己那条

回收站按 `deleted_at DESC` 排序，所以「第一条」就是刚删的那条（自己的）。
流程：记一条 → 删 → 回收站「恢复」→ 时间轴能看到 → 再删 →「永久删除」→
原生二次确认（弹窗按钮是唯一文案「彻底删除」）→ 结束后回收站里**只剩用户自己原来那条**。

### 4.5 导出：面板上的文字是「保存到“文件”」

iOS 26 的系统分享面板里那颗按钮叫 **`保存到“文件”`**（带弯引号），不是「存储到文件」；
面板自带的关闭按钮在可访问性上叫 **`dismiss popup`**。断言和关闭都按这两条写。

> 这一条还顺带证明了**备份文件真的写出来了**：面板上显示文件名
> `lifetrack-backup-2026-10-22` 与 `JSON · 19 KB`。没写出来面板不会弹。

### 4.6 周期：先「记进去」，再制造「越界」

```yaml
- tapOn: '保存记录'          # 今天这条落在区间内 → 存得进
- tapOn: '2026-10-05'        # 把结束日改到 2026-10-05（今天在其后）
- assertVisible: '.*落在区间外.*'   # 黄色预演立刻出现
- tapOn: '保存边界'
- assertVisible: '.*落在新边界之外.*'  # 仓储拒绝，原因原样显示
- assertVisible: '.*已取消修改.*'
```

这条是**「新功能也要能真手点通」**的回归：既验证界面**保存前**本地算出的预演，
也验证仓储**保存时**真的拒绝（不静默删记录）。

### 4.7 统计：切 Chip 之后看「对照窗口」和「说法」

先滚到「对照窗口：…」那行，再点 `较前一段` / `较上年同期`，断言窗口行与结论文案存在。
真跑出来的结论行是：

> 本期 17 条，上年同期没有记录，**无法算变化率**；对照窗口：**2025-10-10 ~ 2025-10-23**（本期 2026-10-09 ~ 2026-10-22）

346 → 少一天的那处偏移正是 **52 周（364 天）** 对齐的效果（星期几与周桶都对得上），
而「对照期为空时不给百分比」这条纪律也在界面上得到确认。

### 4.8 周期记录：删了还能找回来（v5 之后）

`07` 把「周期内记录的删除」走全了一遍：

```yaml
- tapOn: { text: '删除', below: { text: '每日记录' } }   # 软删除（不弹确认）
- assertVisible: '.*回收站.*找回.*'                      # 出现「撤销」提示条
- assertVisible: '.*还没有记录.*'                        # 行真的从列表消失了
- tapOn: '撤销'                                          # 撤销 → 回到列表
- assertVisible: '1 条'
# 再删一次，这回不撤销：去回收站
- tapOn: { text: '恢复', below: { text: '已删除的周期记录' } }   # 恢复 → 该区消失
# 三删，走到底：彻底删除 + 原生二次确认
- tapOn: { text: '永久删除', below: { text: '已删除的周期记录' } }
- tapOn: '彻底删除'
```

「每日记录」那张卡的副标题会显示记录条数，所以 `assertVisible: '1 条'` 能当「它回到列表了」的证据。
另外这条流程**必须和用户自己的软删记录共存**：使用者的回收站里本来就有一条软删的「喝水」，
所以周期区的按钮一律用 `below: 已删除的周期记录` 指到区标题下，绝不用 `index: 0`
——这正是「测试不动用户数据」在代码里的样子。

### 4.9 月视图：点一格是「把那天填进表单」，不是「新增一条记录」

`08` 证明的是月视图的三件事：格子画对了、点得动、点完是**填表单**而不是凭空写库。

```yaml
- assertVisible: '2026 年 10 月'
- assertVisible: '.*日历 2026-10-02，无记录.*'      # 无障碍文案就是选择器
- tapOn: '.*日历 2026-10-02，无记录.*'
- scrollUntilVisible: { element: { text: '当前选中：2026-10-02' }, direction: DOWN }
# 填症状并保存 → 顶部提示写明了日期，证明填的确实是 10-02
- tapOn: '用逗号分隔，例如：头痛、乏力'
- inputText: '头痛,乏力'
- tapOn: '保存记录'
- assertVisible: '.*已保存 2026-10-02.*'
- assertVisible: '.*日历 2026-10-02，有记录（2 个症状）.*'   # 那格自己变了
```

三个细节：

- **`.*` 是必需的**：那格的文字是 `日历 2026-10-02，无记录`（全文匹配，见 3.3），
  而「是不是今天」「有没有记录」都会让它变长。写死全文会在换个日期跑时立刻失败。
- **`当前选中：` 那行要滚下去才看得见**：它排在月视图下面。第一次跑（不加滚动）就是栽在这里——
  格子的蓝框肉眼可见，断言却说找不到，因为元素在屏幕之外。
- **收尾把这条彻底删掉**（软删 → 回收站 → 彻底删除），下次跑还能从头开始；
  流程注释里也写明了它假定 `2026-10-02` 那天还没有记录。

## 5. 一次完整数据流：跑一遍 03，然后看库

1. `maestro test .maestro/flows/03-trash-restore-perma.yaml`
2. 流程在事件页确保「Maestro 喝水」存在 → 记录页点「记录」→ 库里**多一条**未删除记录；
3. 回时间轴 → 点第一行「删除」→ 该行 `deleted_at` 被写上（软删除）；
4. 进回收站 → 点「恢复」→ `deleted_at` 被清空（记录回到时间轴）；
5. 再点「删除」→ 进回收站 → 点「永久删除」→ 弹窗确认 → **整行从表里消失**；
6. 读库核对：总行数**与跑之前一致**（+1 −1），`deleted_at is not null` 的仍然是用户原来那 1 条。

### 没覆盖什么（诚实记录）

- **Android 与真机没跑**；只在 iPhone 16e / iOS 26.3 / Expo Go 58.0.5 上跑过。
- **「选文件导入」没覆盖**：系统文件选择器是另一个 App 的 UI，本项只走到分享面板就关掉了。
  「导出 → 存到「文件」→ 再选回来导入」这条完整链路仍属未验证。
- **周期流程有日期前提**：`05` / `07` 要求运行日期晚于 `2026-10-05`（写这段时是 `2026-10-22`）；
  `08` 另外假定 `Maestro周期` 的 `2026-10-02` 那天还没有记录。
- **数据是累加的**：`01` 每跑一次多一条记录，`05` 每跑一天多一条每日记录；跑多了会出现
  `Maestro…` 开头的定义与记录，可以在 App 里删掉（`07` / `08` 自己造的记录会被真删，不累加）。
- **`03` / `07` / `08` 的真删只删自己刚建的那条**，不代表「用户数据被永久删除」这条路径被覆盖过。
- **组件级测试仍然没有**：这些流程是端到端，界面内部的交互（例如「输入没填完整时不显示预演」）
  依然没有断言。

## 7. 常见问题与排查

### 问题：`Element not found: Text matching regex: 事件`

底部标签栏的文字是 `事件, tab, 3 of 5`，全文匹配不上。用 `.*事件, tab.*`。

### 问题：明明屏幕上看得见，断言却说不可见

三个常见原因：① 部分匹配没写 `.*`；② 元素在**折叠线以下**（要 `scrollUntilVisible`）；
③ 列表行文字被**合并**成了一条长字符串（用 `.*` 包住你认识的那段）。

### 问题：点击「点了没反应」，或者跳到了别的页面

点击打在**键盘**或**标签栏**上了。前者用 `pressKey: Enter` 收键盘；
后者先 `scrollUntilVisible` 把目标滚进安全区再点。

### 问题：`maestro hierarchy` 报 `unable to find utility "simctl"`

本机 `xcode-select -p` 指向 `/Library/Developer/CommandLineTools`。加上
`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`，或一次性
`sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`。

### 问题：点了「永久删除」没反应，弹窗还在

点到了**被弹窗挡住的列表按钮**。两个同名按钮时，`below` 是按顶边比较、命中第一个满足条件的元素，
不是「最近的那个」。办法是让文案不重名（本项目的弹窗按钮叫「彻底删除」），
或者用 `below` 指向**区标题**（如 `已删除的周期记录`）而不是弹窗正文。
详见第 3.7 节。

### 问题：`tapOn: '删除'` 报元素找不到，但屏幕上明明有「删除」

那个「删除」被合并进了整行那一个无障碍元素（第 3.4 节）。要么用 `.*…删除.*` 匹配整行，
要么（本项目已经这么修了）让行内按钮成为独立元素：`src/components/ListRow.tsx` 里
「文字区」自己当无障碍按钮、整行不做无障碍元素。

### 问题：`tapOn: '返回'` 报元素找不到

「返回」在**滚动内容**里，页面一长它就滚出了屏幕（第 3.10 节）。先 `scrollUntilVisible`
把 `返回` 滚回视野再点。**页面变长时，这类失败会突然出现**——不是新功能点坏了，
而是老的「懒得滚」假设被撑破了。

### 问题：跑完库里的数据变多了，是不是把我数据弄坏了

流程只**新增**自己造的 `Maestro*` 数据；`02` / `03` / `07` / `08` 净值 0。
真删那一步删的也是它自己刚建的那条。要清理就在 App 里删掉 `Maestro*` 定义/记录
（注意事件记录不随定义级联，见第 6 节的收尾说明）。**别用 `clearState` 清库**（会连库一起清掉）。

## 8. 学习总结与练习

这一项学到的东西，超出「写 YAML」：

- **可访问性文字就是测试的接口**。元素没有稳定的文字/id，自动化就只能靠坐标——而坐标最脆。
  写界面时顺手把文字写清楚，测试成本会低一个量级。
- **无障碍做得好，自动化才好写（反过来也成立）**。行内按钮被整行「吃掉」这件事，
  读屏用户和测试是同一种受害方式；把它修成独立元素，两边一起变好。
- **断言要挑「只有这里才有」的文字**：能给按钮起不重名的文案，就别去写几何选择器；
  `below` 是「顶边比较」，不是「就近匹配」，用错会点到被弹窗挡住的元素（第 3.7 节）。
- **界面断言 + 直接读库**才是完整证据链：前者证明「用户看到的」，后者证明「真的落盘了」。
- **测试要自产自销、可重复跑**：不依赖手工数据、不用 `clearState`、跑完净值 0。
- **「界面变长」也是一次改动**：多插一张卡片就能让老流程里那句 `tapOn: '返回'` 失效
  （第 3.10 节）。所以加界面之后要跑**全套**，不能只跑新写的那一条——`08` 单跑通过、
  连跑才暴露 `07` 的问题。

练习：

1. 给 `07` 再补一段**「软删除 → 缩小边界 → 恢复被拒」**：记两天 → 删掉较晚的那天 →
   在周期页把结束日提到它之前（应能保存成功）→ 回回收站点「恢复」→ 断言页面顶部的
   红色错误条出现（提示：错误条的文字里有「已经不在所属周期的区间内」）。
2. 把「导入」也接上：先用 `04` 导出一份备份，再写一条流程打开文件选择器选中它
   （提示：这需要跨 App 操作，先想清楚断言什么、以及怎么不污染用户数据）。
3. 用 `maestro studio` 打开记录页，看看「补录」开关打开后多了哪些元素，
   给它写一条「补录过去时间」的流程（注意 `requireNotFuture` 的边界）。
4. 给月视图补一条「翻月」的流程：从 `2026 年 10 月` 点「‹ 上个月」应落到 `2026 年 9 月`
   （但那段周期从 `2026-10-01` 才开始，所以按钮应是**灰的、点不动**）——想一想：
   这条断言为什么比「点得动再翻」更有价值？
